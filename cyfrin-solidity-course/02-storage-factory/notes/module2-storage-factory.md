## Key Concepts Learned

### Deploying a Contract from a Contract

```solidity
import {SimpleStorage} from "./SimpleStorage.sol";

contract StorageFactory {
    SimpleStorage[] public list;

    function createContract() public {
        SimpleStorage newContract = new SimpleStorage(); // deploys!
        list.push(newContract);
    }
}
```

- `new ContractName()` deploys a fresh instance on-chain
- The deployed address is returned and can be stored

## Contract Interaction via ABI

To interact with another contract you need **TWO things**:
1. The contract's **address** (where it lives on-chain)
2. The contract's **ABI** (Application Binary Interface — what functions exist)

```solidity
// Import gives us the ABI automatically
import {SimpleStorage} from "./SimpleStorage.sol";

// Wrap address in the type to get ABI-powered interaction
SimpleStorage ss = SimpleStorage(existingAddress);
ss.store(42);
uint256 n = ss.retrieve();
```

## Inheritance

```solidity
// Parent must mark function as `virtual` to allow override
contract SimpleStorage {
    function store(uint256 num) public virtual { ... }
}

// Child uses `is` keyword and `override`
contract AddFiveStorage is SimpleStorage {
    function store(uint256 num) public override {
        myFavouriteNumber = num + 5;
    }
}
```

### Key rules:
- Parent function must be `virtual`
- Child override must use `override`
- Child inherits ALL public/internal state vars and functions from parent
- Can call parent functions with `super.functionName()`

---

## ABI (Application Binary Interface)

- Defines the interface of a contract: function names, params, return types
- Generated by the Solidity compiler
- Used by front-ends and other contracts to interact with a deployed contract
- You don't write the ABI manually — you `import` the contract type

    ├── creates ──► SimpleStorage[1]  (address: 0xDEF...)
    └── creates ──► SimpleStorage[2]  (address: 0x123...)
